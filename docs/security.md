# الأمان

## نموذج الصلاحيات

### أذونات Android (الحد الأدنى فقط)
| الإذن | السبب | متى يُطلب |
|---|---|---|
| `POST_NOTIFICATIONS` | تذكيرات المواقيت والأذكار | عند تفعيل التذكيرات |
| `SCHEDULE_EXACT_ALARM` | جدولة دقيقة للتذكيرات | عند تفعيل التذكيرات |

لا نطلب: الموقع الدقيق في الخلفية، الوصول للملفات، الكاميرا، الميكروفون، أو أي خدمة خلفية مستمرة.

### بيانات الموقع
- اختيار المدينة يدويًا (لا يحتاج أي إذن) هو المسار الأساسي.
- الموقع الافتراضي **غير معروف** حتى يختار المستخدم مدينة — لا إحداثيات مخترعة.
- الموقع يُستخدم محليًا للحساب فقط ولا يُرسل لخادم في الوضع الحالي.

## قواعد Firestore (عند تفعيل Firebase)

المبادئ المنفذة في `firestore.rules`:
1. **ممنوع `allow read, write: if true`** — لا يوجد أي مسار عام.
2. **كل مستند مملوك لمستخدم واحد** — لا يمكن قراءة أو تعديل بيانات الآخرين بتغيير معرف.
3. **الحقول الحساسة (xp, streak, achievements) خادم فقط** — العميل لا يستطيع منح نفسه نقاطًا.
4. **عضويات الفرق عبر دوال فقط** — لا كتابة مباشرة تسمح بانتحال عضوية.
5. **طلبات الصحبة** — الطرفان فقط يقرآنها، والمستقبِل وحده يغيّر الحالة.
6. **سجلات التدقيق** — غير متاحة للعميل نهائيًا.
7. **حذف الحساب عبر دالة قابلة للاستدعاء فقط** — مع تنظيف البيانات المرتبطة.

## الأسرار

- `.gitignore` يستبعد: `google-services.json`، `key.properties`، `*.keystore`، `*.jks`، `.env*`.
- لا توجد أي مفاتيح في الكود أو المستودع حاليًا.
- قيم تطبيق Flutter ليست أسرارًا بطبيعتها؛ الأسرار الحقيقية (Service Account) تُدار عبر Firebase CLI فقط.

## المخاطر المعروفة

1. **توقيع Release الحالي هو debug-key** — مناسب للاختبار، غير صالح للنشر الرسمي (الحل في `docs/release.md`).
2. **اختبارات قواعد Firestore لم تُشغّل** — تتطلب Emulator Suite؛ القواعد مكتوبة بالمعايير أعلاه لكنها لم تُختبر آليًا بعد.
3. **لا يوجد App Check بعد** — مُخطَّط بعد إعداد Firebase الفعلي.
